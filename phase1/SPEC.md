## 1. 연구 맥락 (연구계획서 ver1.1에서 옮김)

- **참여자**: 대본 기반 캐릭터 분석과 리허설 경험이 있는 성인 배우, 목표 4명·최대 5명.
- **세션 60분**: 동의 확인·소개 5분 → 반구조화 인터뷰 15분 → **프로토타입 사용 및 Think-Aloud 20분** → 사후 인터뷰 15분 → 마무리 5분.
- **프로토타입 과제(계획서 문구)**: "참여자는 초기 프로토타입을 사용하여 대본의 캐릭터 관련 정보를 탐색하고, 특정 정보 간 관계와 그것이 자신의 캐릭터 해석에 미치는 영향을 기록한다. 이후 참여자가 구성한 해석을 기반으로 제시되는 관련 작품, 공연 사례, 배우 인터뷰 등의 드라마투르기적 레퍼런스를 검토하고 참고 여부를 선택한다."
- **고지**: AI 응답이 연구진에 의해 사전에 준비된다는 사실을 **세션 시작 전에** 참여자에게 고지한다. 계획서는 무작위 배정·눈가림·**기만을 사용하지 않는다**고 명시한다.
- **녹음·녹화**: Phase 1은 **음성 녹음만** 승인되어 있다. 화면 녹화는 하지 않는다. 화면 행동은 시스템 로그로 수집한다.
- **수집 데이터(계획서 문구)**: "시스템 내 상호작용 데이터(**모먼트 생성·연결 내역**, **캐릭터 해석 작성 내용**, **드라마투르기적 레퍼런스의 탐색·선택 내역** 등)". 서버에 저장된 데이터는 연구책임자의 암호화된 컴퓨터로 내려받은 뒤 서버에서 삭제한다.
- **개인정보**: 이름·연락처·계좌번호는 사례비 지급 목적으로만 수집한다. 프로토타입에는 어떤 개인식별정보도 입력·저장하지 않으며, 모든 기록은 참여자 코드로 관리한다.
- **대본**: 연구진이 사전에 선정한 연극 대본의 일부 장면. 캐릭터의 과거·관계·사건·행동 정보가 여러 장면에 걸쳐 나타나는 작품.
- **분석**: 전사 자료의 주제 분석(Braun & Clarke, 2006), 연구자 2인 독립 코딩. 분석 대상은 정보 탐색·연결 방식, 정보 간 관계를 해석으로 구성하는 과정, 외부 드라마투르기 자료의 탐색·활용 방식, 기능 요구사항.

### 2.2 v2.1 변경: 범주 대신 비트 (2026-11-04 연구진 논의 결론)

v2는 기획안의 Character Notes를 사용자가 만드는 **범주**(사명·감정·관계 등)로 구현했다. 연구진 논의 결과 이를 **비트**로 바꾼다.

- **근거**: 한 줄 한 줄 해석을 다는 점은 질적 자료 코딩과 같다. 하지만 대본에서는 감정과 상황이 순간순간 바뀌기 때문에, 한 대본을 범주로 묶으면 두루뭉술해지고 범주를 만드는 일 자체가 성립하지 않을 수 있다. 한 장면 안에서도 세부적으로 달라지는 흐름을 반영하려면 비트가 단위가 되어야 한다.
- **결정**: 비트 사용 채택. 범주 뷰 자리에 범주 대신 비트를 넣어 **비트 뷰**로 만든다.
- **구현 원칙**: v3의 비트 기능(비트 범위, 목적, 문장 단위 행동동사, 범위 메모, 완료 표시, 범위 다시 선택, 겹침 금지)을 그대로 가져오고, 인터페이스는 v2(두 화면, 3분할, 드래그 선택)를 유지한다. v3의 별도 비트 상세 화면과 1초 누르기 조작은 가져오지 않는다.
- **연구계획서와의 관계**: 과제("캐릭터 관련 정보를 탐색하고, 특정 정보 간 관계와 그것이 해석에 미치는 영향을 기록")와 수집 항목은 비트로도 그대로 충족된다. 계획서의 "모먼트"는 이 구현에서 비트(와 Backstory)에 해당한다.

### 2.3 제외

- 사용자 범주(만들기·이름·색·순서·강조·미분류) — v2.1에서 제거
- v3의 비트 상세 화면, 1초 누르기 → 클릭 방식, 비트 메뉴 띠
- 완성보드(초목표·관통하는 해석·열린 질문), 해석본 .md 저장
- 줄 사이 자유 메모(생각 / 전사·비등장 시간). 대본 밖 정보는 Backstory(4.3.4)로 대신한다.
- AI 사이드바의 [시대배경] [인물 관계] [자유 질문] 버튼. 레퍼런스 요청의 진입점은 **참여자가 구성한 해석** 하나뿐이다(4.7).
- 화면 녹화를 전제로 한 운영 절차

## 3. 용어

| 용어 | 정의 |
| --- | --- |
| **비트** (beat) | 한 장면 안에서 참여자가 직접 고른 연속된 대사 범위. 같은 장면의 다른 비트와 겹칠 수 없다. 대본 순서대로 B1, B2…로 번호와 색이 붙는다. |
| **목적** | 비트마다 한 줄. "~하기 위해" |
| **행동동사** | 비트 안에서 참여자가 고른 문장들에 붙이는 동사 한 줄. "상대를 ~하다". 문장 단위로 묶이며(동사1, 동사2…), 한 문장은 한 동사에만 속한다. |
| **메모** | 비트 안의 문구 범위에 다는 자유 메모. 다른 표시와 겹쳐도 된다. |
| **완료** | 목적과 행동동사가 1개 이상 있는 비트 |
| **Backstory** | 대본 밖 정보(인물의 과거, 비등장 시간)를 적는 자유 기술 항목. 근거 장면·줄을 지정할 수 있다. 비트와 같은 목록에 들어가고 캔버스에 올릴 수 있다. |
| **노드** | 화면 2 캔버스 위에 놓인 비트(또는 Backstory). |
| **연결** (link) | 참여자가 비트 노드와 해석 노드 사이에 그은 선. |
| **해석** (interpretation) | 참여자가 연결한 비트들로부터 구성한 캐릭터 해석. **해석명**과 **해석 작성**(본문)을 가진다. |
| **레퍼런스** | 연구진이 미리 검증한 드라마투르기적 자료 카드(관련 작품의 인물, 공연 사례, 배우 인터뷰, 역사·문화 자료). |

UI 표기: Character Journey, **Beats**, Scripts, Connections, Dramaturgy Agent. 버튼·안내 문구는 한국어.

## 4. 참여자 화면

### 4.1 입장과 단계 (기존 구현 재사용)

- 입장: 참여자 코드 입력(형식 `^P\d{2}$`) → `sessions/{uid}/runs/{code}` 생성, `phase='practice'`.
- 연습: 짧은 연습 장면에서 조작을 익힌다. **20분 사용 시간 안에 포함하며 2분 이내**로 진행자가 구두 안내한다. 연습 기록은 `mode='practice'`로 분리 저장하고 과제 화면에 보이지 않는다.
- 연구자가 `phase='task'`로 바꾸면 [과제 시작] 버튼 → 누른 시각을 `taskStartAt`과 `task_start` 이벤트로 기록하고 과제 대본으로 전환.
- `phase='done'`이면 모든 입력 잠금, "수고하셨습니다" 표시. 같은 계정으로 다음 참여자를 받기 위한 [다음 참여자 코드 입력] 유지.
- 새로고침 시 화면, 열린 장면, 열린 비트, 캔버스 위치, 선택 상태를 복원.
- 페이지에는 과제 설명이나 조작 안내를 넣지 않는다(구두 안내). 빈 상태의 placeholder 문구만 허용.

### 4.3 Scripts (화면 1 오른쪽)

#### 4.3.1 대본 표시
- 패널 머리: "Scripts" + 현재 장면 제목. 장면 이동은 Character Journey에서 한다.
- 줄 번호, 화자(굵게), 지문(기울임·회색). 대본은 수정 불가. 표적 인물 대사 강조 토글(기본 꺼짐).
- **모든 장면**(표적 인물 등장 여부와 무관)에서 비트를 만들 수 있다. [결정] v3는 표적 장면만 허용했으나, RQ1(흩어진 정보의 연결)에 맞춰 넓힌다.

#### 4.3.2 드래그 선택과 메뉴
대본을 드래그하면 선택한 글자가 **끊김 없이 이어지는 하이라이트**로 표시되고(글자마다 테두리를 그리지 않는다), 선택 끝 근처에 메뉴가 뜬다. Shift+클릭으로 선택을 늘린다. Esc로 닫는다. 선택이 어디에 걸리느냐에 따라 메뉴가 달라진다.

| 선택 위치 | 메뉴 | 결과 |
| --- | --- | --- |
| 비트가 없는 곳 | **[비트로 만들기]** | 고른 범위 그대로 비트 생성 → Beats에서 그 비트가 펼쳐지고 목적 칸에 커서 |
| 한 비트 안 | **[행동동사] [메모]** | 행동동사: 선택과 겹치는 문장들을 새 동사 그룹으로 묶음(다른 그룹에 있던 문장은 옮겨 옴) → 동사 칸에 커서. 메모: 고른 범위에 메모 → 메모 칸에 커서 |
| 기존 비트와 일부만 겹침 | 메뉴 없음 | "B2와 겹쳐서 비트를 만들 수 없습니다" 알림, `beat_overlap_rejected` 기록 |
| [범위 다시 선택] 중 | **[B1 범위를 여기로 바꾸기]** | 다른 비트와 겹치지 않으면 범위 변경. 행동동사·메모는 유지하고, 새 범위 밖으로 나간 것은 "범위 밖"으로 표시 |

#### 4.3.3 표시
- 비트 범위: 비트 색 옅은 배경 + 시작 위치에 `B1` 칩.
- 행동동사 문장: 조금 진한 배경 + 아래 실선 + 그룹 첫 문장 앞에 `동사1` 라벨.
- 메모 범위: 점선 밑줄.
- 하이라이트를 클릭하면 Beats에서 그 비트가 펼쳐진다. 비트 카드·노드에 마우스를 올리면 대본의 해당 범위도 진해진다(양방향).

#### 4.3.4 Backstory
- Character Journey 맨 위 **Backstory** 칸(또는 Beats의 [+ Backstory])을 누르면 Scripts 자리에 Backstory 패널이 열린다.
- 대본 밖 정보를 1~3줄로 적고, 선택적으로 근거 장면·줄을 지정해 추가한다. 목록에서 고치거나 삭제할 수 있다.
- Backstory 항목은 Beats 목록 맨 위에 나오고, 비트처럼 캔버스에 올려 해석에 연결할 수 있다. 목적·행동동사는 없다.

### 4.4 Beats (화면 1 가운데, 화면 2 왼쪽)

- 패널 머리: "Beats" + "비트 n · 완료 m".
- 목록 순서: **Backstory** → 장면별 묶음(장면 제목 소제목) → 장면 안에서는 대본 순서.
- **접힌 카드**: `B1` 칩, 장면·줄 범위, ✓ 완료, (화면 2에서) 캔버스 표시. 인용 2줄, 목적 한 줄, 행동동사 목록(칩), 메모 개수.
- **펼친 카드**(한 번에 하나): 인용 전체, **목적** 입력("~하기 위해"), **행동동사** 그룹별 카드(동사N · 묶인 문장 · 동사 입력 "상대를 ~하다" · 삭제), **메모** 카드(인용 · 메모 입력 · 삭제), [범위 다시 선택] [비트 삭제](화면 1에서만).
- 카드를 누르면 펼쳐지고, 화면 1에서는 Scripts가 그 비트 위치로 이동해 강조한다. 펼친 카드의 머리를 다시 누르면 접힌다. 화면 2에서는 캔버스의 노드로 이동한다.
- 비트 삭제는 두 번 확인한다. 캔버스 노드와 연결도 함께 지워지고, 남은 비트는 다시 번호가 매겨진다.
- 모든 편집은 800ms 디바운스 저장, 포커스가 빠지면 즉시 저장. before/after 기록.

### 4.5 Character Journey (화면 1 왼쪽)

- 세로 목록: **Backstory**(개수) → 장면 1 … 장면 N.
- 각 칸: 장면 제목, 표적 라벨, 표적 인물 등장 여부("등장 X"), 그 장면 비트의 **번호 칩**(B1 B2…). 완료한 비트는 칩이 채워진다.
- 칸을 누르면 Scripts가 그 장면을 연다(`scene_open`). 현재 장면 칸 강조.

### 4.6 Connections (화면 2 가운데)

- **비트 노드**: Beats의 카드를 캔버스로 끌어 놓는다. 노드: `B1` 칩, 장면·줄, ✓, 목적, 인용(최대 3줄), 행동동사(최대 3개 + "외 n"). 같은 비트는 한 번만 놓인다(이미 있으면 그 노드로 이동).
- **해석 노드**: [+ 해석] → 해석명(한 줄), 해석 작성(여러 줄), 채택한 레퍼런스 칩.
- **연결**: 비트 노드 오른쪽 점을 해석 노드로 끈다. 단순 연결, 방향은 비트 → 해석, 관계 이름 없음. 한 비트를 여러 해석에 연결할 수 있다. 선 클릭 → [연결 삭제] 또는 Delete.
- 노드 이동(머리 드래그), 캔버스 빼기(✕, 비트 자체는 남음), 빈 곳 드래그로 캔버스 이동. 확대·축소 없음.
- 해석 노드를 클릭하면 선택 상태가 되고 Dramaturgy Agent의 대상이 된다.

### 4.7 Dramaturgy Agent (화면 2 오른쪽)

- 고정 고지문: **"응답은 연구진이 미리 준비한 자료 중에서 골라 보내 드립니다."**
- 요청 대상: 선택한 해석 노드(또는 드롭다운).
- **[이 해석으로 레퍼런스 찾기]** 활성 조건: 대상 해석에 **연결된 비트 2개 이상** + **해석 작성이 비어 있지 않음**. 비활성일 때 이유를 한 줄로 보인다.
- 요청 시 **해석 스냅샷** 저장: 해석명, 해석 작성, 연결된 비트 각각의 번호·위치·인용·목적·행동동사(동사와 묶인 문장)·메모.
- 응답: "'{해석명}' 참조됨" + "비슷한 상황에 처한 인물들을 알려드릴게요. 이 인물들은 어떻게 행동했는지 살펴보세요." + 카드 1~4장(출처 유형, 제목, 요약, 인용, 출처 링크).
- 카드마다 [채택] [보류] [배제] + 이유 한 줄. 채택하면 해석 노드에 "참고: {카드 제목}" 칩. **해석 본문에는 아무것도 자동으로 입력하지 않는다.**
- 화면 1에 있을 때 응답이 오면 [연결·해석] 탭에 점만 표시하고 화면을 자동 전환하지 않는다. AI가 먼저 말을 걸지 않는다.

## 6. 응답 풀 카드

```json
{
  "ref-01": {
    "type": "reference",
    "title": "극A의 인물 ○○",
    "play": "작품명",
    "character": "인물명",
    "sourceType": "play | performance | interview | history",
    "branch": "분기 이름",
    "polarity": "similar | contrast",
    "summary": "그 인물이 놓인 상황과 그때의 행동을 2~3문장으로.",
    "quote": "짧은 인용(선택, 2문장 이내)",
    "sourceUrl": "https://…",
    "keywords": ["분기 추천용 단어"],
    "tags": []
  }
}
```

- `type`: `reference` | `fallback`. (v1~v3의 `background`, `relation` 유형은 쓰지 않는다. 역사·문화 자료는 `reference` + `sourceType: history`.)
- 카드 원칙: 실재하고 출처로 확인할 수 있는 자료만. 요약 2~3문장, 인용 2문장 이내. "~하게 연기하라" 같은 지시나 참여자 해석에 대한 평가 문구 금지.
- 분량 기준 [결정]: 과제 장면에서 예상되는 해석 분기 3~4개 × 유사·대조 × 2장 = **레퍼런스 12~16장** + fallback 1장. 세션 사이에 자주 나온 분기는 카드를 추가하되, 추가 시점을 기록한다.
- 운영 원칙: 요청이 없으면 보내지 않는다. 같은 분기의 요청에는 참여자가 달라도 가능한 한 같은 카드를 보낸다. 목표 응답 시간은 요청 후 15~30초.

## 9. 운영 (MANUAL 개정 사항)

- **계정**: 참여자 개인 claude.ai 계정 초대는 하지 않는다(계획서에 없는 개인정보 사용). 팀이 만든 **연구용 계정**을 편집자로 초대해 두고, 참여자는 그 계정으로 로그인된 노트북(대면) 또는 Zoom 원격 제어로 사용한다. 기록은 참여자 코드별로 분리된다.
- **녹음**: Zoom은 **음성만** 녹음한다. 화면 녹화하지 않는다.
- **고지**: 세션 시작 시 구두로 "AI 응답은 연구진이 미리 준비한 자료 중에서 연구자가 골라 보내 드립니다"를 고지한다(화면 고지문과 같은 내용).
- **역할**: 진행자(Zoom·Think-Aloud 촉구·과제 안내), 위저드(콘솔 전담, 카메라·마이크 끔, 게시자 계정).
- **20분 시간 배분** [결정]: 연습 2분 → 화면 1 수집·정리 약 8분 → 화면 2 연결·해석·레퍼런스 약 10분. 진행자는 과제 시작 후 **10분**에 "만든 비트들을 연결해 해석을 만들어 보세요"로 화면 2 전환을 안내한다(전환 강요는 아님, 마커로 기록).
- **과제 안내 문구**(구두): "대본을 읽으며 이 인물을 해석하는 데 필요한 부분을 비트로 나누고, 비트마다 목적과 행동동사를 적어 주세요. 대본에 없는 과거는 Backstory에 적으셔도 됩니다. 그다음 비트들을 연결해 해석을 만들고, 그 해석으로 레퍼런스를 찾아 참고할지 정해 주세요. 생각나는 것을 소리 내어 말씀해 주세요."
- **데이터**: 세션 후 JSON·CSV 내보내기 → 암호화된 컴퓨터로 이동 → 세션 데이터 삭제. 저장 위치(claude.ai 서버)를 동의서 개인정보 항목에 명시.

## 12. 완료 기준 (구현 후 직접 확인하고 결과를 보고할 것)

1. 화면 1에 Character Journey · Beats · Scripts가 동시에 보인다.
2. 드래그 선택이 글자마다 테두리 없이 이어지는 하이라이트로 보인다.
3. 비트가 없는 곳을 드래그하면 [비트로 만들기]가 뜨고, 표적 장면이 아닌 장면에서도 비트가 만들어지며, 카드가 펼쳐지고 목적 칸에 커서가 간다.
4. 비트 안을 드래그하면 [행동동사] [메모]가 뜬다. 행동동사는 문장 단위로 묶이고, 메모는 고른 범위에 달린다.
5. 목적과 행동동사가 있으면 ✓ 완료와 Journey 칩 채움이 바로 바뀐다.
6. 대본에 비트 배경·`B1` 칩, 행동동사 밑줄·`동사1` 라벨, 메모 점선이 보인다.
7. 기존 비트와 일부만 겹치는 선택은 거부된다.
8. [범위 다시 선택]으로 범위를 바꿔도 행동동사·메모가 남는다.
9. Journey에 장면별 비트 번호 칩이 보인다.
10. Backstory를 추가하면 Beats 맨 위에 보인다.
11. 화면 2에서 비트를 캔버스로 끌면 목적·행동동사가 보이는 노드가 되고, 연결 비트 2개 + 해석 작성이 있어야 레퍼런스 버튼이 켜진다.
12. 새로고침 후 노드·연결·해석이 그대로다.
13. 위저드 요청 상세에 비트의 목적·행동동사·메모가 보이고, 응답이 참여자에게 표시된다.
14. 채택하면 해석 노드에 칩이 붙고 해석 본문은 바뀌지 않는다.
15. 위저드 실시간 미러에 비트 목록이 보인다.
16. 비트를 삭제하면 노드·연결이 함께 지워지고 번호가 다시 매겨진다.
17. 8절의 이벤트가 기록되고 JSON 내보내기에 `beats`가 들어 있다.
18. 페이지에 범주 UI, "일부 응답은…" 문구, 완성보드가 남아 있지 않다.
19. 확인하지 못한 항목은 못 했다고 알린다.
