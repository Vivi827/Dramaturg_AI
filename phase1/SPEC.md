## 1. 연구 맥락 (연구계획서 ver1.1에서 옮김)

- **참여자**: 대본 기반 캐릭터 분석과 리허설 경험이 있는 성인 배우, 목표 4명·최대 5명.
- **세션 60분**: 동의 확인·소개 5분 → 반구조화 인터뷰 15분 → **프로토타입 사용 및 Think-Aloud 20분** → 사후 인터뷰 15분 → 마무리 5분.
- **프로토타입 과제(계획서 문구)**: "참여자는 초기 프로토타입을 사용하여 대본의 캐릭터 관련 정보를 탐색하고, 특정 정보 간 관계와 그것이 자신의 캐릭터 해석에 미치는 영향을 기록한다. 이후 참여자가 구성한 해석을 기반으로 제시되는 관련 작품, 공연 사례, 배우 인터뷰 등의 드라마투르기적 레퍼런스를 검토하고 참고 여부를 선택한다."
- **고지**: AI 응답이 연구진에 의해 사전에 준비된다는 사실을 **세션 시작 전에** 참여자에게 고지한다. 계획서는 무작위 배정·눈가림·**기만을 사용하지 않는다**고 명시한다.
- **녹음·녹화**: Phase 1은 **음성 녹음만** 승인되어 있다. 화면 녹화는 하지 않는다. 화면 행동은 시스템 로그로 수집한다.
- **수집 데이터(계획서 문구)**: "시스템 내 상호작용 데이터(**모먼트 생성·연결 내역**, **캐릭터 해석 작성 내용**, **드라마투르기적 레퍼런스의 탐색·선택 내역** 등)". 서버에 저장된 데이터는 연구책임자의 암호화된 컴퓨터로 내려받은 뒤 서버에서 삭제한다.
- **개인정보**: 이름·연락처·계좌번호는 사례비 지급 목적으로만 수집한다. 프로토타입에는 어떤 개인식별정보도 입력·저장하지 않으며, 모든 기록은 참여자 코드로 관리한다.
- **대본**: 연구진이 사전에 선정한 연극 대본의 일부 장면. 캐릭터의 과거·관계·사건·행동 정보가 여러 장면에 걸쳐 나타나는 작품.
- **분석**: 전사 자료의 주제 분석(Braun & Clarke, 2006), 연구자 2인 독립 코딩. 분석 대상은 정보 탐색·연결 방식, 정보 간 관계를 해석으로 구성하는 과정, 외부 드라마투르기 자료의 탐색·활용 방식, 기능 요구사항.

## 4. 참여자 화면

### 4.1 입장과 단계 (기존 구현 재사용)

- 입장: 참여자 코드 입력(형식 `^P\d{2}$`) → `sessions/{uid}/runs/{code}` 생성, `phase='practice'`.
- 연습: 짧은 연습 장면에서 조작을 익힌다. **20분 사용 시간 안에 포함하며 2분 이내**로 진행자가 구두 안내한다. 연습 기록은 `mode='practice'`로 분리 저장하고 과제 화면에 보이지 않는다.
- 연구자가 `phase='task'`로 바꾸면 [과제 시작] 버튼 → 누른 시각을 `taskStartAt`과 `task_start` 이벤트로 기록하고 과제 대본으로 전환.
- `phase='done'`이면 모든 입력 잠금, "수고하셨습니다" 표시. 같은 계정으로 다음 참여자를 받기 위한 [다음 참여자 코드 입력] 유지.
- 새로고침 시 화면, 열린 장면, 캔버스 위치, 선택 상태를 복원.
- 페이지에는 과제 설명이나 조작 안내를 넣지 않는다(구두 안내). 빈 상태의 placeholder 문구만 허용.

### 4.2 전체 레이아웃

```
+-----------------------------------------------------------------------+
| [수집·정리] [연결·해석]          대본 제목 · 표적 인물            상태  |
+-----------------------------------------------------------------------+
| 화면 1                                                                |
| +----------------+--------------------+------------------------------+|
| |Character       |Character Notes     |Scripts        Scene 3        ||
| |Journey         |                    |                              ||
| | Backstory  ●   |● 나의 사명          |  (하이라이트된 대본)          ||
| | Scene1  ● ●    |   · 모먼트           |                              ||
| | Scene2  ●      |● 나의 감정          |                              ||
| | Scene3  ●      |   · 모먼트           |                              ||
| |  …             |○ 미분류             |                              ||
| +----------------+--------------------+------------------------------+|
|   약 20%            약 25%               약 55%                        |

```

- 상단 고정 바에 화면 전환 탭 두 개: **[수집·정리]**(화면 1), **[연결·해석]**(화면 2). 전환마다 `screen_switch` 기록.
- 데스크톱 1280px 이상 전용. 한글 본문 16px 이상. 대본 영역은 종이 대본 느낌(기존 스타일 재사용).
- 세 패널은 각자 세로 스크롤. 패널 사이 구분선은 고정(크기 조절 기능 없음).

### 4.3 Scripts (화면 1 오른쪽)

#### 4.3.1 대본 표시
- 패널 머리: "Scripts" + 현재 장면 제목. 장면 이동은 Character Journey에서 한다(Scripts에 장면 탭 없음).
- 줄 번호, 화자(굵게), 지문(기울임·회색). 대본은 수정 불가.
- **모든 장면**(표적 인물 등장 여부와 무관)에서 모먼트를 만들 수 있다.
- 표적 인물 대사 강조 토글(기본 꺼짐) 유지.

#### 4.3.2 모먼트 만들기 (하이라이트)
1. 대본에서 마우스로 텍스트를 드래그하면 선택 끝 근처에 작은 메뉴가 뜬다: **[모먼트로 저장]** · ✕. Shift+클릭으로 선택을 늘린다. Esc로 닫는다.
2. [모먼트로 저장] → 메뉴가 범주 목록으로 바뀐다: 기존 범주들 + **[미분류]** + **[새 범주…]**(이름 입력 후 Enter). 고르는 즉시 저장.
3. 저장 범위는 고른 글자 그대로(문장 단위로 넓히지 않음): `{sceneId, start:{line, offset}, end:{line, offset}}`. 여러 줄에 걸쳐도 된다.
4. 저장된 모먼트는 **범주 색**으로 하이라이트. 미분류는 회색.
5. 모먼트 범위끼리 겹쳐도 된다(겹친 부분은 두 색이 섞여 보이지 않도록 나중 것을 위에 칠하고 아래쪽 밑줄로 앞 것을 표시).
6. 하이라이트를 클릭하면 Character Notes의 해당 모먼트로 스크롤·강조. 하이라이트에 마우스를 올리면 Notes의 항목도 강조(양방향).
7. 기록: `moment_create {momentId, sceneId, range, categoryId, quote}`.

#### 4.3.3 Backstory
- Character Journey 맨 위 **Backstory(대본 이전 이야기, 전사)** 칸을 누르면 Scripts 자리에 Backstory 패널이 열린다.
- Backstory 패널: 대본 안에서 근거를 찾은 대본 밖 정보(예: "어린 시절부터 일기를 써 왔다")를 **자유 기술 모먼트**로 추가한다. [+ Backstory 모먼트] → 한 줄~세 줄 입력 → 범주 선택.
- Backstory 모먼트는 `source='backstory'`, 대본 범위 없음. 선택적으로 "근거 장면"(장면 id·줄 번호)을 지정할 수 있다.
- [결정] 기획안 As-Is 그림이 Backstory를 서사의 첫 칸으로 그린 것을 따른다. **[확인 필요]**

### 4.4 Character Notes (화면 1 가운데, 화면 2 왼쪽)

- 패널 머리: "Character Notes" + [+ 범주].
- **범주**: 참여자가 만들고 이름을 정한다. 이름 변경, 색 변경(8색 팔레트), 삭제(확인 필요, 소속 모먼트는 미분류로 이동). 순서 바꾸기는 드래그.
  - [결정] **빈 상태로 시작**하고, 범주가 없을 때만 placeholder로 "예: 나의 사명, 나의 감정, ○○과의 관계"를 보인다(기획안 와이어프레임의 예시). 시스템이 범주를 미리 만들지 않는다. **[확인 필요]**
- **모먼트 항목**: 범주 아래에 대본 순서(Backstory → 장면 순 → 줄 → 글자)로 나열. 각 항목: 장면·줄 위치, 인용(최대 2줄 말줄임), 메모(있으면).
  - 항목 클릭 → 화면 1이면 Scripts가 해당 장면·위치로 이동해 강조. 화면 2면 캔버스에 노드가 있을 경우 그 노드로 이동.
  - 항목 메뉴: 메모 쓰기/고치기(한 줄), 범주 바꾸기(드롭다운 또는 다른 범주로 드래그), 삭제(확인, 연결된 노드·연결도 함께 삭제됨을 표시).
- 맨 아래 **미분류** 그룹(모먼트가 있을 때만 표시).
- 범주 머리를 클릭하면 그 범주만 강조 모드(Journey의 점과 Scripts의 하이라이트에서 다른 범주를 흐리게). 다시 누르면 해제. `category_focus` 기록.
- 모든 편집은 800ms 디바운스 저장, before/after 기록(`category_*`, `moment_edit`).

### 4.5 Character Journey (화면 1 왼쪽)

- 세로 목록: **Backstory** → 장면 1 … 장면 N.
- 각 칸: 장면 제목, 표적 인물 등장 여부 표시(대본 데이터에서 표적 인물의 대사가 있는지로 계산; 등장 없음은 옅게 "등장 X" 라벨), 그 장면 모먼트의 **범주 색 점**(범주별 1개, 점 옆 개수는 2개 이상일 때만).
- 칸을 누르면 Scripts가 그 장면을 연다(`scene_open`). 현재 장면 칸 강조.
- 표적 장면은 "표적" 라벨.
- 점에 마우스를 올리면 해당 범주명·개수 툴팁.

### 4.6 Connections (화면 2 가운데)

```
+-----------------+--------------------------------------------+-------------+
| Character Notes | Connections                       [+ 해석]  | Dramaturgy  |
| (4.4 동일,       |  ┌──────────┐                                | Agent       |
|  드래그 출발점)   |  │● 사명 A   │──┐   ┌────────────────────┐   | (4.7)       |
|                 |  │Scene 1    │  ├──▶│해석명               │   |             |
|                 |  │"대사…"    │  │   │해석 작성            │   |             |
|                 |  └──────────┘  │   │[참고: 극A의 인물 ○○]│   |             |
|                 |  ┌──────────┐  │   └────────────────────┘   |             |
|                 |  │● 관계 A   │──┘                            |             |
|                 |  └──────────┘                                |             |
+-----------------+--------------------------------------------+-------------+
     약 22%                       약 53%                            약 25%
```

- **모먼트 노드 만들기**: Character Notes의 모먼트 항목을 캔버스로 드래그해 놓는다. 노드 카드: 범주 색 점 + 범주명, 장면 위치, 인용(최대 3줄). 같은 모먼트는 캔버스에 **한 번만** 놓인다(이미 있으면 그 노드로 이동·강조). `node_place`.
- **해석 노드 만들기**: [+ 해석] → 캔버스 빈 자리에 해석 노드 생성(`interp_create`). 해석 노드: **해석명**(한 줄, placeholder "예: 사명을 떠올리고 격분한 ○○"), **해석 작성**(여러 줄, placeholder "이 정보들을 이어 보면 …"), 채택한 레퍼런스 칩 영역.
- **연결**: 모먼트 노드 오른쪽 연결점을 드래그해 해석 노드에 놓는다(`link_create {momentId, interpId}`). 연결선은 SVG 꺾은선. 연결선 클릭 → 선택 → Delete 또는 ✕로 삭제(`link_delete`).
  - [결정] 연결은 **모먼트 → 해석** 방향만 있고 관계 이름을 붙이지 않는다(기획안 와이어프레임과 동일한 단순 연결). **[확인 필요]**
  - [결정] 한 모먼트 노드를 **여러 해석에 연결할 수 있다**. **[확인 필요]**
- 노드 이동: 드래그. 위치는 저장(`node_move`는 드래그 종료 시 1회).
- 노드 삭제: 캔버스에서 빼기(모먼트 자체는 Notes에 남음, 연결도 삭제). 해석 노드 삭제는 확인 후, 연결·첨부 칩 함께 삭제.
- 캔버스: 빈 곳 드래그로 이동(pan). 확대·축소 없음. 캔버스 크기는 노드 위치에 맞춰 늘어난다.
- 해석 노드를 클릭하면 **선택 상태**(굵은 테두리)가 되고 Dramaturgy Agent의 대상이 된다.
- 해석명·해석 작성은 800ms 디바운스 저장, `interp_edit {field, before, after}`.

### 4.7 Dramaturgy Agent (화면 2 오른쪽)

- 패널 머리: "Dramaturgy Agent". 바로 아래 고정 고지문: **"응답은 연구진이 미리 준비한 자료 중에서 골라 보내 드립니다."** (기획안·계획서의 기만 미사용 원칙. 기존의 "일부 응답은…" 문구는 쓰지 않는다.)
- 요청 대상: 캔버스에서 선택한 해석 노드. 선택이 없으면 해석 목록 드롭다운.
- **[이 해석으로 레퍼런스 찾기]** 버튼 활성 조건: 대상 해석에 **연결된 모먼트 2개 이상** + **해석 작성이 비어 있지 않음**.
  - 근거: 계획서 "특정 정보 **간** 관계", 기획안 "여러 정보를 직접 연결하여 나만의 해석 구성".
  - 비활성 툴팁: "모먼트를 두 개 이상 연결하고 해석을 적어 주세요."
- 요청 시 그 순간의 **해석 스냅샷**을 함께 저장: 해석명, 해석 작성, 연결된 모먼트 목록(범주명, 장면 위치, 인용, 메모). `ref_request`.
- 대기 중: "자료를 찾는 중…". 응답은 실시간 구독으로 받는다.
- **응답 표시** (기획안 와이어프레임 형식):
  - 머리: "'{해석명}' 참조됨" (해석명이 비어 있으면 "해석 {n}")
  - 고정 안내 한 줄: "비슷한 상황에 처한 인물들을 알려드릴게요. 이 인물들은 어떻게 행동했는지 살펴보세요."
  - 카드 1~4장. 카드: 출처 유형 라벨(희곡 / 공연 / 배우 인터뷰 / 역사·문화 자료), **제목**(예: "극A의 인물 ○○"), 상황 요약 2~3문장, 짧은 인용(있으면, 2문장 이내), 출처 링크(새 탭, `ref_link_open`).
  - 카드마다 [채택] [보류] [배제] + 이유 한 줄(선택) → `ref_decision`. 결정을 바꾸면 새 결정으로 기록(덮어쓰지 않음).
  - **채택** 시 해당 해석 노드에 "참고: {카드 제목}" 칩이 붙는다. 칩 클릭 → 카드로 스크롤. **해석 본문에 자동으로 아무것도 입력하지 않는다.**
- 지난 요청·응답은 해석별로 시간순으로 남는다. 패널 상단에 해석 필터(전체 / 선택한 해석).
- 화면 1에 있을 때 응답이 오면 [연결·해석] 탭에 점만 표시하고 화면을 자동 전환하지 않는다.
- AI가 먼저 말을 걸거나 제안을 밀어 넣지 않는다(요청이 있을 때만 응답).

## 6. 응답 풀 카드

```json
{
  "ref-01": {
    "type": "reference",
    "title": "극A의 인물 ○○",
    "play": "작품명",
    "character": "인물명",
    "sourceType": "play | performance | interview | history",
    "branch": "분기 이름",
    "polarity": "similar | contrast",
    "summary": "그 인물이 놓인 상황과 그때의 행동을 2~3문장으로.",
    "quote": "짧은 인용(선택, 2문장 이내)",
    "sourceUrl": "https://…",
    "keywords": ["분기 추천용 단어"],
    "tags": []
  }
}
```

- `type`: `reference` | `fallback`. (v1~v3의 `background`, `relation` 유형은 쓰지 않는다. 역사·문화 자료는 `reference` + `sourceType: history`.)
- 카드 원칙: 실재하고 출처로 확인할 수 있는 자료만. 요약 2~3문장, 인용 2문장 이내. "~하게 연기하라" 같은 지시나 참여자 해석에 대한 평가 문구 금지.
- 분량 기준 [결정]: 과제 장면에서 예상되는 해석 분기 3~4개 × 유사·대조 × 2장 = **레퍼런스 12~16장** + fallback 1장. 세션 사이에 자주 나온 분기는 카드를 추가하되, 추가 시점을 기록한다.
- 운영 원칙: 요청이 없으면 보내지 않는다. 같은 분기의 요청에는 참여자가 달라도 가능한 한 같은 카드를 보낸다. 목표 응답 시간은 요청 후 15~30초.

## 9. 운영 (MANUAL 개정 사항)

- **계정**: 참여자 개인 claude.ai 계정 초대는 하지 않는다(계획서에 없는 개인정보 사용). 팀이 만든 **연구용 계정**을 편집자로 초대해 두고, 참여자는 그 계정으로 로그인된 노트북(대면) 또는 Zoom 원격 제어로 사용한다. 기록은 참여자 코드별로 분리된다.
- **녹음**: Zoom은 **음성만** 녹음한다. 화면 녹화하지 않는다.
- **고지**: 세션 시작 시 구두로 "AI 응답은 연구진이 미리 준비한 자료 중에서 연구자가 골라 보내 드립니다"를 고지한다(화면 고지문과 같은 내용).
- **역할**: 진행자(Zoom·Think-Aloud 촉구·과제 안내), 위저드(콘솔 전담, 카메라·마이크 끔, 게시자 계정).
- **20분 시간 배분** [결정]: 연습 2분 → 화면 1 수집·정리 약 8분 → 화면 2 연결·해석·레퍼런스 약 10분. 진행자는 과제 시작 후 **10분**에 "모은 정보를 연결해 해석을 만들어 보세요"로 화면 2 전환을 안내한다(전환 강요는 아님, 마커로 기록).
- **과제 안내 문구**(구두): "대본을 읽으며 이 인물을 해석하는 데 필요한 정보를 골라 모으고, 나만의 방식으로 정리해 주세요. 그다음 정보들을 연결해 해석을 만들고, 그 해석으로 레퍼런스를 찾아 참고할지 정해 주세요. 생각나는 것을 소리 내어 말씀해 주세요."
- **데이터**: 세션 후 JSON·CSV 내보내기 → 암호화된 컴퓨터로 이동 → 세션 데이터 삭제. 저장 위치(claude.ai 서버)를 동의서 개인정보 항목에 명시.

## 12. 완료 기준 (구현 후 직접 확인하고 결과를 보고할 것)

1. 샘플 데이터로 참여자 화면이 열리고, 화면 1의 세 패널이 동시에 보인다.
2. 표적 장면이 아닌 장면에서도 드래그 → [모먼트로 저장] → 범주 선택으로 모먼트가 만들어지고, 범주 색 하이라이트가 칠해진다.
3. 범주를 만들고 이름·색을 바꾸고 삭제하면 소속 모먼트가 미분류로 옮겨진다.
4. Journey의 장면별 범주 점이 모먼트 추가·삭제·범주 변경에 맞춰 바뀌고, 장면 클릭으로 Scripts가 이동한다.
5. Backstory 모먼트를 추가할 수 있고 Journey 첫 칸에 점이 표시된다.
6. 화면 2에서 모먼트를 캔버스로 드래그하면 노드가 생기고, 해석 노드에 연결선을 그을 수 있으며, 새로고침 후 위치·연결·해석 내용이 그대로다.
7. 연결 모먼트가 2개 미만이거나 해석 작성이 비어 있으면 레퍼런스 버튼이 비활성이다.
8. 두 브라우저(참여자/위저드)로 요청 → 콘솔 큐(해석 스냅샷·분기 후보 표시) → 카드 전송 → Agent 패널 표시("'해석명' 참조됨")까지 2초 안에 동작한다.
9. 채택하면 해석 노드에 칩이 붙고, 해석 본문은 바뀌지 않는다.
10. 8절의 이벤트가 시간순으로 기록되고, JSON·CSV 내보내기에 포함된다.
11. 참여자 계정으로 `pool`, `wizardlog`, 다른 참여자 기록을 읽을 수 없다.
12. 페이지 어디에도 "일부 응답은…" 문구, 비트·행동동사·완성보드 UI가 남아 있지 않다.
13. 확인하지 못한 항목은 못 했다고 알린다.
