# Act & Connect 운영 매뉴얼 (Phase 1, v4)

이 프로토타입은 claude.ai Artifact로 게시된 웹 페이지 하나다. 같은 링크를 열어도 **게시한 연구자에게는 위저드 콘솔**, **초대받은 연구용 계정에는 참여자 화면**이 열린다. 레퍼런스 응답은 실제 LLM이 아니라 연구자가 콘솔에서 미리 검증한 카드를 골라 보내는 Wizard-of-Oz 방식이다. 설계 기준은 [`../SPEC.md`](../SPEC.md), 연구 절차 기준은 연구계획서 ver1.1이다.

## 1. 한눈에 보는 흐름

1. 연구자가 실제 대본과 응답 풀을 넣는다(세션 1주 전).
2. 연구용 계정을 편집자로 초대해 둔다(최초 1회).
3. 세션(60분): 동의 확인·소개 5분 → 반구조화 인터뷰 15분 → **프로토타입 사용 및 Think-Aloud 20분** → 사후 인터뷰 15분 → 마무리 5분.
4. 사후 인터뷰에서 콘솔의 사후 타임라인을 화면 공유한다.
5. 내보내기(JSON·CSV) → 암호화된 컴퓨터에 저장 → 세션 데이터 삭제.

## 2. 사전 준비

### 2.1 대본과 응답 풀 넣기
대본과 카드는 페이지 코드가 아니라 아티팩트 데이터베이스에 들어간다. 게시한 Claude 대화에서 "샘플 데이터를 지우고 첨부한 대본과 응답 풀로 교체해 줘"라고 요청한다. 형식은 `data/sample-config.json`, `data/sample-pool.json`과 같다.

- `config/script`: 과제 대본. `{title, targetCharacter, scenes:[{id, title, isTarget, lines:[{n, speaker, text, kind: line|direction}]}]}`. 캐릭터 정보가 여러 장면(등장하지 않는 장면 포함)에 흩어진 작품을 고른다.
- `config/practice`: 연습용 짧은 장면(같은 형식).
- `config/settings`: `showPolarity`(참여자에게 유사/대조 라벨을 보일지, 기본 false).
- `pool/<카드ID>`: `type`은 `reference` 또는 `fallback`. 레퍼런스는 `title`(예: "극A의 인물 ○○"), `play`, `character`, `sourceType`(play·performance·interview·history), `branch`(해석 분기), `polarity`(similar·contrast), `summary`, `quote`, `sourceUrl`, `keywords`(분기 추천용 단어)를 채운다.

카드 원칙: 실재하고 출처로 확인할 수 있는 자료만 쓴다. 요약은 2~3문장, 인용은 2문장 이내. "~하게 연기하라" 같은 지시나 참여자 해석에 대한 평가는 넣지 않는다. 분량 기준은 예상 분기 3~4개 × 유사·대조 × 2장 = **12~16장** + fallback 1장. 카드 선정 기준은 논문 방법 절에 쓸 수 있게 따로 기록한다.

### 2.2 스스로 점검하기
- 콘솔 오른쪽 위 **[참여자 화면 미리보기]**로 참여자 화면을 직접 써 볼 수 있다(연구자 계정의 연습용 기록으로 따로 쌓인다).
- 요청→응답 흐름은 연구용 계정으로 다른 브라우저에서 코드 `P99`로 입장해 확인하고, 끝나면 콘솔에서 P99를 내보내기 → 삭제한다.
- **파일럿 1회**로 20분 안에 화면 1과 화면 2를 모두 거치는지 확인한다.

## 3. 계정

- 참여자 **본인 claude.ai 계정은 쓰지 않는다**(연구계획서에 없는 개인정보 사용이 생긴다).
- 팀이 만든 **연구용 계정** 하나를 아티팩트 공유(Share)에서 **편집자(Editor)**로 초대한다. **공개 링크 공유는 켜지 않는다.**
- 참여자는 그 계정으로 로그인된 노트북(대면) 또는 Zoom 원격 제어로 사용한다. 기록은 참여자 코드별로 분리된다.
- 한 참여자가 끝나면 콘솔에서 단계를 '완료'로 바꾸고, 참여자 화면의 [다음 참여자 코드 입력]으로 넘어간다.

## 4. 세션 진행

역할: **진행자**는 Zoom 진행·과제 안내·Think-Aloud 촉구, **위저드**는 콘솔만 본다. 콘솔은 게시자 계정에서만 열리므로 위저드가 게시자여야 한다. 위저드는 카메라와 마이크를 끈다.

**녹음**: Zoom은 **음성만** 녹음한다(Phase 1 승인 범위). 화면 녹화는 하지 않는다. 화면 행동은 시스템 로그로 남는다.

**고지(세션 시작 시 구두)**: "프로토타입의 AI 응답은 연구진이 미리 준비한 자료 중에서 연구자가 골라 보내 드립니다." 참여자 화면에도 같은 문구가 늘 보인다.

**과제 안내(구두)**: "대본을 읽으며 이 인물을 해석하는 데 필요한 정보를 골라 모으고, 나만의 방식으로 정리해 주세요. 그다음 정보들을 연결해 해석을 만들고, 그 해석으로 레퍼런스를 찾아 참고할지 정해 주세요. 생각나는 것을 소리 내어 말씀해 주세요."

| 시간 | 참여자 화면 | 연구자 콘솔에서 할 일 |
| --- | --- | --- |
| 입장 | 참여자 코드 입력(P01 형식) | 왼쪽 세션 목록에 코드가 뜨는지 확인 |
| 연습 (2분) | 연습 장면으로 하이라이트·범주·캔버스 조작 | 6장의 조작을 구두로 안내. 단계는 '연습' 유지 |
| 과제 전환 | [과제 시작] 버튼이 나타남 | 상단 단계 버튼을 **과제**로 |
| 수집·정리 (약 8분) | Journey·Notes·Scripts에서 모먼트 수집과 범주 정리 | 실시간 미러로 범주·모먼트를 봄 |
| 10분 체크포인트 | — | 진행자가 "모은 정보를 연결해 해석을 만들어 보세요"로 안내하고, 위저드는 [탐색 전환] 마커 |
| 연결·해석·레퍼런스 (약 10분) | Connections에서 연결과 해석, Dramaturgy Agent에서 요청 | 요청 큐 → 5장 |
| 관찰 | — | [멈칫] [탐색 전환] [AI 반영] [기타] 마커 + 메모 |
| 종료 | "수고하셨습니다", 입력 잠김 | 단계를 **완료**로 |
| 사후 인터뷰 | — | [사후 타임라인] 탭을 화면 공유하며 "이때 왜 이 모먼트들을 연결하셨나요?" |

참고: 콘솔의 '최근 이벤트'는 최대 10초 늦게 보인다. 화면·장면·모먼트·해석은 1~2초 안에 반영된다. 참여자가 새로고침해도 작업과 화면 상태가 복원된다.

## 5. Dramaturgy Agent 운영 (Wizard-of-Oz)

### 5.1 참여자 쪽에서 보이는 것
- 고정 고지문: "응답은 연구진이 미리 준비한 자료 중에서 골라 보내 드립니다."
- [이 해석으로 레퍼런스 찾기]는 고른 해석에 **모먼트가 2개 이상 연결되고 해석 작성이 비어 있지 않을 때만** 켜진다.
- 응답은 "'해석명' 참조됨" + "비슷한 상황에 처한 인물들을 알려드릴게요…" + 카드 1~4장으로 보인다.
- 카드마다 [채택] [보류] [배제]와 이유 칸. 채택하면 해석 노드에 "참고: 카드 제목" 칩이 붙는다. 해석 본문에는 아무것도 자동으로 들어가지 않는다.
- 참여자가 화면 1에 있을 때 응답이 오면 [연결·해석] 탭에 점만 표시되고 화면이 저절로 바뀌지 않는다.

### 5.2 연구자가 응답하는 순서
1. 오른쪽 요청 큐에서 요청을 고른다(가장 오래된 대기 요청이 자동 선택).
2. 요청 내용에 해석명·해석 작성·연결된 모먼트(범주·위치·인용·메모)와 **분기 후보**(각 분기 keywords가 나온 횟수)가 보인다. 결정은 연구자가 한다.
3. 응답 풀에서 카드 1~4장을 체크한다(키보드 1~4). 분기·유사/대조·출처 유형 필터와 검색을 쓸 수 있다.
4. 필요하면 '선택 사유'를 한 줄 적는다(참여자에게 보이지 않음).
5. [보내기] 또는 Enter. 목표는 요청 후 15~30초 안이다.
6. 맞는 카드가 없으면 `fallback` 카드를 보낸다. **즉석에서 문구를 지어내지 않는다.**

운영 원칙: 요청이 없으면 보내지 않는다. 같은 분기의 요청에는 참여자가 달라도 가능한 한 같은 카드를 보낸다. 해석을 평가하거나 연기를 지시하는 문구는 보내지 않는다. 자주 나온 분기는 세션 사이에 카드를 추가하고, 추가 시점을 기록한다.

## 6. 참여자 조작 (연습 단계에서 구두로 안내)

| 하고 싶은 것 | 방법 |
| --- | --- |
| 장면 이동 | 왼쪽 Character Journey에서 장면 누르기 |
| 모먼트 만들기 | Scripts에서 문구를 드래그 → [모먼트로 저장] → 범주 고르기(또는 새 범주 이름 입력). Shift+클릭으로 선택을 늘림. Esc로 취소 |
| 대본 밖 정보 | Journey 맨 위 Backstory → 내용·범주·근거 장면을 적고 [+ Backstory 모먼트] |
| 범주 만들기·고치기 | Notes의 [+ 범주], 이름 칸에 바로 입력, 색 점을 누르면 색 변경, ⋮⋮를 끌어 순서 변경, ✕로 삭제(모먼트는 미분류로) |
| 모먼트 정리 | 모먼트를 다른 범주로 끌어 놓기, 또는 항목 위에 마우스를 올려 범주 선택·메모·삭제 |
| 한 범주만 보기 | 범주의 [강조] |
| 원문 위치로 가기 | Notes의 모먼트 클릭 / 대본 하이라이트 클릭 → Notes의 항목 |
| 연결 화면으로 | 상단 [연결·해석] |
| 노드 만들기 | Notes의 모먼트를 가운데 캔버스로 끌어 놓기 |
| 해석 만들기 | [+ 해석] → 해석명과 해석 작성 |
| 연결하기 | 모먼트 노드 오른쪽 동그라미를 해석 노드로 끌기. 선을 누르고 [연결 삭제] 또는 Delete |
| 캔버스 이동 | 빈 곳을 끌기. 노드는 머리를 끌어 이동 |
| 레퍼런스 받기 | 해석 노드를 고르고 오른쪽 [이 해석으로 레퍼런스 찾기] |

## 7. 세션 후 데이터 처리

1. 콘솔에서 해당 세션을 고르고 **[JSON 내보내기]**와 **[이벤트 CSV]**를 저장한다.
2. 파일을 연구책임자의 암호화된 컴퓨터로 옮긴다.
3. 내보내기를 한 뒤에만 **[세션 데이터 삭제]**가 켜진다. 두 번 눌러 삭제한다.

내보낸 JSON에는 범주·모먼트·노드·해석·연결·요청(해석 스냅샷)·응답·결정·이벤트·위저드 기록이 모두 들어 있다. CSV는 이벤트를 과제 시작 기준 경과 시간과 함께 한 줄씩 담는다. 분석 지표(해석이 걸친 장면 수, 채택 후 해석 수정 여부 등)는 SPEC.md 8절을 따른다.

## 8. 문제 해결

| 화면 메시지·증상 | 원인과 조치 |
| --- | --- |
| "초대받은 계정으로 로그인한 뒤 다시 열어 주세요" | 로그인하지 않았거나 claude.ai 밖(예: 저장한 HTML 파일)에서 열었음 |
| "저장 권한이 없습니다. 연구자에게 알려 주세요" | 편집자가 아닌 권한으로 초대됐거나 공개 링크가 켜져 있음 → 공유 설정 확인 |
| "연구 준비 중입니다" | `config/script` 또는 `config/practice`가 비어 있음 → 2.1 |
| 레퍼런스 버튼이 안 켜짐 | 해석을 고르지 않았거나, 연결 모먼트가 2개 미만이거나, 해석 작성이 비어 있음 |
| 응답이 참여자에게 안 보임 | 참여자가 화면 1에 있음. [연결·해석] 탭의 점을 누르면 보임 |

## 9. IRB 관련 확인

- 운영 방식(연구용 계정, 음성 녹음만, 시스템 로그 수집)은 연구계획서 ver1.1의 Phase 1 승인 범위 안에 있다.
- 데이터는 claude.ai(Anthropic) 서버에 저장된다. 동의서의 개인정보·연구자료 항목에 저장 위치와 "내려받은 뒤 서버에서 삭제" 절차를 적는다.
- 프로토타입은 이름·이메일을 받지 않는다.
