# Act & Connect 사용 매뉴얼 (Phase 1)

이 프로토타입은 claude.ai Artifact로 게시된 웹 페이지 하나다. 같은 링크를 열어도 **게시한 연구자에게는 위저드 콘솔**, **초대받은 참여자에게는 참여자 화면**이 열린다. AI 응답은 실제 LLM이 아니라 연구자가 콘솔에서 미리 준비한 카드를 골라 보내는 Wizard-of-Oz 방식이다.

## 1. 한눈에 보는 흐름

1. 연구자가 실제 대본과 응답 풀을 넣는다(세션 1주 전).
2. 공유 메뉴에서 참여자 계정을 **편집자**로 초대한다(세션 전날).
3. 세션: 참여자가 코드 입력 → 연습 → 연구자가 단계를 '과제'로 전환 → 참여자가 [과제 시작] → 비트 분석과 AI 요청 → 연구자가 응답 카드 전송 → '완료'.
4. 사후 인터뷰에서 콘솔의 사후 타임라인을 화면 공유한다.
5. 내보내기(JSON·CSV) → 암호화된 컴퓨터에 저장 → 세션 데이터 삭제 → 공유에서 참여자 제거.

## 2. 사전 준비 (연구자)

### 2.1 대본과 응답 풀 넣기
대본과 카드는 페이지 코드가 아니라 아티팩트 데이터베이스에 들어간다. 이 대화(또는 아티팩트를 만든 Claude 대화)에서 아래처럼 요청하면 된다.

> 샘플 데이터를 지우고 첨부한 대본과 응답 풀로 교체해 줘.

형식은 저장소의 `data/sample-config.json`, `data/sample-pool.json`과 같다.

- `config/script`: 과제용 대본. 장면 배열이며, 표적 장면 하나에 `isTarget: true`. 각 줄은 `{n, speaker, text, kind: "line" | "direction"}`.
- `config/practice`: 연습용 짧은 장면(같은 형식).
- `config/settings`: `showPolarity`(참여자에게 유사/대조 라벨을 보일지).
- `pool/<카드ID>`: `type`은 `background`(시대배경) · `relation`(인물 관계) · `reference`(레퍼런스) · `fallback`(범위 밖 고정 문구). 레퍼런스는 `branch`(해석 분기), `polarity`(similar/contrast), `keywords`(분기 추천용 단어)를 채운다.

카드 원칙: 실재하고 출처로 확인할 수 있는 자료만 쓴다. 요약은 2~3문장, 인용은 2문장 이내, "~하게 연기하라" 같은 지시문은 넣지 않는다.

### 2.2 스스로 점검하기
- 콘솔 오른쪽 위 **[참여자 화면 미리보기]**로 참여자 화면을 직접 써 볼 수 있다. 이 기록은 연구자 계정의 연습용 기록으로 따로 쌓인다.
- 한 계정으로는 콘솔과 참여자 화면을 동시에 띄울 수 없다. 요청→응답 흐름은 2.3의 테스트 계정으로 확인한다.

### 2.3 테스트 계정으로 권한 확인 (첫 세션 전 1회)
1. 팀 밖 계정 하나를 3장의 방식으로 편집자로 초대한다.
2. 그 계정으로 다른 브라우저에서 링크를 열고 코드 `P99`로 입장한다.
3. 비트를 하나 만들고 새로고침한다. 남아 있으면 성공이다.
4. 콘솔에서 P99가 보이는지, 요청을 보내고 받을 수 있는지 확인한다.
5. 끝나면 콘솔에서 P99를 내보내기 → 삭제한다.

## 3. 참여자 초대하기

1. 아티팩트 상단의 **공유(Share)**를 연다.
2. 참여자의 claude.ai 계정 이메일을 입력하고 권한을 **편집자(Editor)**로 고른다.
3. **공개 링크 공유는 켜지 않는다.** 켜면 외부 편집자의 저장 권한이 사라지고, 링크를 아는 누구나 볼 수 있다.
4. 세션 당일 Zoom 채팅으로 링크를 보낸다.
5. 세션이 끝나면 공유에서 참여자를 제거한다.

- 외부 이메일 초대나 편집자 권한이 메뉴에 보이지 않으면 **연구용 계정 방식**을 쓴다. 팀이 만든 연구용 계정 하나를 편집자로 초대해 두고, 참여자는 그 계정으로 로그인된 노트북(대면) 또는 Zoom 원격 제어로 사용한다. 한 계정을 여러 참여자가 써도 기록은 참여자 코드별로 분리된다.
- 참여자 본인 계정으로 초대하는 경우, 이메일을 외부 플랫폼 초대에 쓴다는 점을 동의서에 적어야 한다.

참여자 안내문 예시:
> 세션에서는 웹 프로토타입을 사용합니다. 사용하시려면 claude.ai 계정이 필요합니다. 세션 전날까지 가입하신 이메일 주소를 알려 주시면 초대를 보내드립니다. 당일에는 PC(크롬 권장)에서 로그인한 상태로 Zoom에 접속해 주세요. 프로토타입에는 이름이나 이메일을 입력하지 않으며, 세션이 끝나면 접근 권한을 해제합니다.

## 4. 세션 진행 (연구자)

역할: **진행자**는 Zoom 진행과 Think-Aloud 촉구, **위저드**는 콘솔만 본다. 콘솔은 아티팩트를 게시한 계정에서만 열리므로, 위저드를 맡을 사람이 게시자여야 한다. 위저드는 카메라와 마이크를 끈다(타이핑 소리 주의).

| 단계 | 참여자 화면 | 연구자 콘솔에서 할 일 |
| --- | --- | --- |
| 입장 | 참여자 코드 입력(P01 형식) | 왼쪽 세션 목록에 코드가 뜨는지 확인 |
| 연습 | 연습 장면으로 조작 익히기 | 3장의 조작을 구두로 안내. 단계는 '연습' 유지 |
| 과제 전환 | [과제 시작] 버튼이 나타남 | 상단 단계 버튼을 **과제**로 |
| 과제 | 참여자가 [과제 시작]을 누르면 표적 대본으로 바뀜 | 경과 시간이 표시됨. 실시간 미러로 비트·메모를 봄 |
| 정리 | [완성보드]에서 장면 전체 해석을 쓰고 비트별 해석을 훑어봄 | 실시간 미러의 '완성보드' 블록에 입력이 보임. 화면 표시가 '완성보드'로 바뀜 |
| AI 요청 | 사이드바에서 요청 | 오른쪽 요청 큐에 뜨고 대기 시간(초)이 올라감 → 5장 |
| 관찰 | — | [멈칫] [탐색 전환] [AI 반영] [기타] 마커 + 메모 |
| 종료 | "수고하셨습니다", 입력 잠김 | 단계를 **완료**로 |
| 사후 인터뷰 | — | [사후 타임라인] 탭을 화면 공유하며 "이때 왜 AI를 여셨나요?" |

참고:
- 콘솔의 '최근 이벤트'는 최대 10초 늦게 보인다. 참여자가 보는 장면·줄·모드는 1~2초 안에 반영된다.
- 참여자가 새로고침해도 작업, 단계, 열려 있던 비트가 복원된다.
- [알림음 켜짐]을 눌러 두면 새 요청이 올 때 소리가 난다.

## 5. AI 사이드바 운영 (Wizard-of-Oz)

### 5.1 참여자 쪽에서 보이는 것
- 사이드바는 기본으로 접혀 있다. 참여자가 열기 전에는 아무것도 먼저 보내지 않는다.
- 상단에 "일부 응답은 연구진이 미리 준비했습니다."가 항상 보인다.
- 요청 종류: [시대배경], [인물 관계], 자유 질문, [내 해석으로 레퍼런스 찾기].
- 레퍼런스 버튼은 **목적과 행동동사를 채운 비트가 하나 이상** 있어야 켜진다. 누르면 완성된 비트를 고르는 목록이 뜬다.
- 레퍼런스 카드에는 [채택] [보류] [배제]와 이유 입력칸이 있다. 채택하면 해당 비트에 카드 제목 칩이 붙는다. 본문이 자동으로 들어가지는 않는다.
- 사이드바가 접혀 있을 때 응답이 오면 세로 탭에 점만 표시되고 저절로 펼쳐지지 않는다.

### 5.2 연구자가 응답하는 순서
1. 오른쪽 요청 큐에서 요청을 고른다(가장 오래된 대기 요청이 자동으로 선택된다).
2. 레퍼런스 요청이면 위에 참여자의 비트 스냅샷(목적·동사·메모)과 **분기 후보**가 보인다. 숫자는 각 분기 keywords가 참여자 글에 나온 횟수다. 결정은 연구자가 한다.
3. 응답 풀에서 카드를 1~4장 체크한다. 키보드 1~4로도 고를 수 있다. 유형 필터는 요청 종류에 맞춰 자동으로 바뀐다.
4. 필요하면 '선택 사유'를 한 줄 적는다(참여자에게 보이지 않음).
5. [보내기] 또는 Enter. 목표는 요청 후 15~30초 안이다.
6. 풀에 맞는 카드가 없으면 `fallback` 카드(범위 밖 고정 문구)를 보낸다. 즉석에서 답을 지어내지 않는다.

운영 원칙:
- 요청이 없으면 아무것도 보내지 않는다.
- 같은 유형의 요청에는 참여자가 달라도 가능한 한 같은 카드를 보낸다.
- 해석을 평가하거나 연기를 지시하는 문구는 보내지 않는다.
- 자주 나온 범위 밖 질문은 세션 사이에 새 카드로 만들어 풀에 추가한다.

## 6. 참여자 조작 (연습 단계에서 구두로 안내)

| 하고 싶은 것 | 방법 |
| --- | --- |
| 비트 만들기 | 표적 장면에서 시작 글자를 **1초 길게 누름**(원형 표시) → 끝 글자를 **클릭**. Esc로 취소. 다른 비트와 겹치면 저장되지 않음 |
| 비트 열기 | 아래 비트 메뉴에서 카드 클릭 → 위 영역이 비트 상세 화면으로 바뀜 |
| 목적 쓰기 | 상세 화면 상단 '목적' 칸 |
| 행동동사 | 상세 화면에서 문장을 드래그 → [행동동사] → 오른쪽 칸에 동사 입력. Shift+클릭으로 선택 범위를 다음 문장까지 늘림 |
| 메모 | 드래그 → [메모] → 밑줄이 생기고 오른쪽에 메모 카드 |
| 대본으로 돌아가기 | [← 대본으로] |
| 비트 범위 고치기 | 상세 화면의 [범위 다시 선택] → 대본에서 다시 길게 누름 → 클릭 |
| 대본 메모 | 대본 줄 사이에 마우스를 올리면 [+ 메모]. 종류는 '생각' 또는 '전사·비등장 시간' |
| 대사 강조 | 대본 위쪽의 '<인물> 대사 강조' 체크 |
| 완성보드 열기 | 대본 상단, 비트 상세 상단, 또는 아래 비트 메뉴 오른쪽의 [완성보드] |

### 6.1 완성보드

비트 편집과 대본 메모를 마친 뒤, 지금까지의 작업을 **한 장의 캐릭터 해석본**으로 보는 화면이다. 연습과 과제 단계의 보드는 따로 저장된다.

| 영역 | 내용 | 편집 |
| --- | --- | --- |
| 머리 | 대본 제목·표적 장면, '<인물> 캐릭터 해석본', 비트·완성·대본 메모·채택 레퍼런스 개수 | — |
| 장면 전체 | 이 장면에서 인물이 원하는 것(~하기 위해), 관통하는 해석 한 줄, 아직 열어 둔 질문 | 여기서 직접 입력. 0.8초 뒤 자동 저장 |
| 씬 순서로 보기 | 대본 메모(생각·전사)와 비트의 목적·행동동사·비트 메모를 장면→줄 순서로 한 목록에 | 체크해서 고르고 [조합 만들기]. [이동]으로 원래 위치로 |
| 조합 | 고른 항목 묶음과 "이 조합에서 읽은 것" 한 줄 | [이 조합으로 레퍼런스 찾기], [삭제] |
| 행동의 흐름 | 비트 순서대로 B1 → B2 → … 와 각 비트의 행동동사·목적. 미완성 비트는 '미완성' 표시 | 카드를 누르면 그 비트 상세로 이동 |
| 비트별 해석 | 비트마다 목적, 행동동사와 해당 문장, 비트 메모, 채택한 레퍼런스 | [비트 열기]로 이동해 고침 |
| 참고한 레퍼런스 | AI 카드 중 채택·보류한 것과 이유, 출처 링크 | AI 사이드바에서 결정 변경 |

조합으로 레퍼런스를 요청하면 위저드 콘솔의 요청 큐에 "레퍼런스 · 조합 N"으로 뜨고, 요청 내용에 조합 항목·해석·완성보드 세 칸이 함께 보입니다. 채택한 카드는 그 조합에 붙습니다. AI 사이드바의 [내 해석으로 레퍼런스 찾기] 목록에도 조합이 나타납니다.

[해석본 저장 (.md)]을 누르면 `P01_해석본.md` 같은 마크다운 파일이 참여자 컴퓨터에 저장된다. 사후 인터뷰에서 함께 보거나, 참여자에게 자기 해석본을 돌려줄 때 쓴다. 완료 단계에서는 보드가 읽기 전용이 된다.

## 7. 세션 후 데이터 처리

1. 콘솔에서 해당 세션을 고르고 **[JSON 내보내기]**와 **[이벤트 CSV]**를 저장한다. 또는 Claude에게 "P01 세션 데이터를 읽어 정리해 줘"라고 요청해도 된다.
2. 파일을 연구책임자의 암호화된 컴퓨터로 옮긴다.
3. 내보내기를 한 뒤에만 **[세션 데이터 삭제]**가 켜진다. 두 번 눌러 삭제한다.
4. 공유 메뉴에서 참여자를 제거한다.

내보낸 JSON에는 비트·메모·대본 메모·완성보드·요청·응답·결정·이벤트·위저드 기록이 모두 들어 있다. CSV는 이벤트를 과제 시작 기준 경과 시간과 함께 한 줄씩 담는다.

## 8. 문제 해결

| 화면 메시지·증상 | 원인과 조치 |
| --- | --- |
| "초대받은 계정으로 로그인한 뒤 다시 열어 주세요" | 로그인하지 않았거나 claude.ai 밖(예: 저장한 HTML 파일)에서 열었음 |
| "저장 권한이 없습니다. 연구자에게 알려 주세요" | 편집자가 아닌 권한으로 초대됐거나 공개 링크가 켜져 있음 → 공유 설정 확인 |
| "연구 준비 중입니다" | `config/script` 또는 `config/practice`가 비어 있음 → 2.1 |
| 콘솔에 참여자가 안 보임 | 참여자가 아직 코드를 입력하지 않았음. 같은 계정으로 콘솔을 열었다면 '미리보기'로 표시됨 |
| 응답이 참여자에게 안 보임 | 참여자의 사이드바가 접혀 있으면 탭에 점만 표시됨. 열면 보임 |
| 다음 참여자를 같은 계정으로 받아야 함 | 단계를 '완료'로 바꾸면 참여자 화면에 [다음 참여자 코드 입력]이 나타남 |

## 9. IRB 관련 확인

- 전체 화면 녹화는 계획서 ver1.1의 Phase 1 승인 범위(음성 녹음)에 없으므로 변경 심의 또는 동의서 수정이 필요하다.
- 데이터는 claude.ai(Anthropic) 서버에 저장된다. 동의서의 개인정보 항목에 저장 위치와 삭제 절차를 적는다.
- 프로토타입은 이름·이메일을 저장하지 않는다. 이메일–참여자 코드 대응표는 연구자 컴퓨터에 따로 보관한다.
